Reverse-proxy HTTPS detection (REQUIRED at every cutover)
---------------------------------------------------------

Caddy terminates TLS and reverse-proxies to the WP container over plain HTTP (with header_up X-Forwarded-Proto https). WordPress checks $_SERVER['HTTPS'], which is empty on that inner HTTP hop, so once WP_HOME/WP_SITEURL are https it fires an http->https canonical redirect that loops forever (front-end loops; /wp-json/ still 200 because REST skips canonical). IGS hit this.

Fix - add to each site's wp-config.php (above the require_once wp-settings.php line):

    /* Honor reverse-proxy TLS (Caddy terminates HTTPS) */
    if ( isset($_SERVER['HTTP_X_FORWARDED_PROTO']) && $_SERVER['HTTP_X_FORWARDED_PROTO'] === 'https' ) {
        $_SERVER['HTTPS'] = 'on';
    }

Add this as part of the HTTPS-enable step for every remaining cutover, not just when a loop appears. Also check the DB `home`/`siteurl` options don't still point at a dev/staging domain (IGS had home = http://melvyn.wordpress.developyn.com); correct them.

Container resource tuning (applied 2026-07-08)
----------------------------------------------

All WP containers run wordpress:*-apache = Apache prefork + mod_php, so RAM scales with the number of Apache children. Defaults (StartServers 5 / MaxSpareServers 10 / MaxConnectionsPerChild 0) left busy sites holding ~10 idle children (pedmore was 755MB idle). Tuned down; freed ~2GB (host used 3.8G -> 1.9G, available 4.0G -> 5.9G).

- Shared drop-in files bind-mounted read-only into every WP service via docker-compose.yml:
  - /srv/wordpress/config/apache-tune.conf -> /etc/apache2/conf-enabled/zz-tune.conf
      StartServers 2, MinSpareServers 2, MaxSpareServers 4, MaxRequestWorkers 24, MaxConnectionsPerChild 500
  - /srv/wordpress/config/opcache-tune.ini -> /usr/local/etc/php/conf.d/zz-opcache-tune.ini
      opcache.memory_consumption=48 (was 128), interned_strings_buffer=8, max_accelerated_files=4000
- mem_limit: 512m added per WP service (runaway cap).
- New sites: add the same two volume mounts + mem_limit block to their compose service.
- To re-tune: edit the two files, then docker compose restart. To roll back: restore docker-compose.yml.bak-tune-<ts> and docker compose up -d.
- Not done (revisit only if packing many more sites): mod_php -> PHP-FPM pm=ondemand, which drops idle sites to ~zero workers but means moving off the apache image to fpm behind Caddy php_fastcgi.
